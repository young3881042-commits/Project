# ai-assitant 앱 작업 인수인계

> 이 문서는 과거 참고 화면 요청의 이력이다. 현재 제품 기준은 `LIFEHUB_MAINTENANCE_KO.md`와 `WEB_UI_UX_AUDIT_KO.md`이며, 아래의 4탭·빠른 기록 요구는 더 이상 현행 요구가 아니다.

이 문서는 모바일 앱 화면 개편 작업을 안전하게 이어가기 위한 공개 가능한 요약이다.
개인 대화 원문이나 계정 정보는 포함하지 않으며, 구현 상태는 항상 현재 작업 트리를
기준으로 다시 확인한다.

## 복구된 요청 요약

- 업로드된 모바일 참고 화면 8장을 현재 기능과 대조해 앱 전체의 시각 언어를 통일한다.
- 기존 미커밋 작업을 먼저 확인해 보존하고, 독서 기능은 제품에서 제거한다.
- 웹 브라우저 화면에 그치지 않고 Android 휴대폰에 직접 설치할 수 있는 APK를 만든다.
- 다른 환경에서도 `git pull` 뒤 같은 소스·작업지침·검증된 APK를 사용할 수 있게 한다.
- 작업이 끝나면 웹, API, Docker, PWA, APK와 주요 모바일 동작을 검증하고 원격 Git에
  커밋·push한다.

## 제품 목표와 고정 조건

- 설치 대상과 앱 표기는 `ai-assitant`로 통일한다.
- 기본 앱 경로는 `/app`이며, `/`은 별도 홈을 렌더링하지 않고 `/app`으로 넘긴다.
- 최종 화면은 Android 휴대폰에서 앱처럼 사용할 수 있는 모바일 우선 UI여야 한다.
- 기존 미커밋 변경을 먼저 검토하고 보존한다. 다른 작업을 되돌리거나 덮어쓰지 않는다.
- 하단 핵심 내비게이션은 `홈`, `메모`, `일정`, `더보기`의 네 영역으로 유지한다.
- **독서 기능은 제품 범위에서 제외한다.** 홈 카드, 일정 예시, 더보기 모듈, 라우트,
  백업 데이터, 서비스 워커 캐시, 아이콘과 독서 전용 소스에 진입점이 남지 않게 한다.
  기존 `/reading` 방문자는 깨진 화면 대신 안전한 앱 화면으로 이동시켜도 된다.
- 참고 이미지에 있는 Guest/로그인 UI는 시각 참고일 뿐이다. 현재 제품에서 이미
  Guest/member 노출을 제거한 방향이라면 다시 추가하지 않는다.

## 참고 이미지와 화면 대응

| 번호 | 화면 | 반영할 핵심 구조 |
| --- | --- | --- |
| 1 | 홈 | 인사 영역, 다음 할 일, 빠른 기록, 오늘 일정, 오늘 상태 |
| 2 | 메모 | 빠른 메모 입력, 첨부·태그, 추천 태그, 최근 메모, 즐겨찾기 |
| 3 | 일정 | 일정 요약, 주간 날짜, 상태 필터, 알림 안내, 시간순 목록, 일정 추가 |
| 4 | 더보기 | 계정 상태, 서비스 안내, 모듈 바로가기, 설정·도움말·피드백 |
| 5 | 독서 | 구현하지 않음. 독서 제외 여부를 확인하는 참고 자료로만 사용 |
| 6 | 운동 | 운동 시간·종류, 요약 수치, 선택 신체 정보, 날짜·시간·메모, 저장 |
| 7 | 가계부 | 월 지출 요약, 예산 진행률, 카테고리, 빠른 입력, 최근 거래 |
| 8 | AI 여행 | 기본 정보, 취향 선택, 선택 조건 요약, 계획 생성의 단계형 흐름 |

공통 시각 언어는 흰 배경, 얇은 회색 테두리와 절제된 그림자, 넉넉한 둥근 모서리,
청록색 강조색, 짙은 남색 주요 버튼이다. 상단 제목과 날짜, 카드 간격, 고정 하단 탭,
Android safe area를 모든 화면에서 일관되게 적용한다. 이미지의 예시 문구와 숫자는
고정값으로 복사하지 않고 실제 상태와 저장 데이터로 표시한다.

## 화면별 구현 요구

### 홈

- 다음 행동을 한눈에 이해할 수 있는 대표 카드와 실행 버튼을 둔다.
- 메모, 일정, 운동, 지출의 빠른 기록 진입점을 제공한다.
- 오늘 일정은 시간순으로 요약하고 전체 일정으로 이동할 수 있게 한다.
- 상태 카드와 오늘 체크 영역에는 독서 항목을 넣지 않는다.

### 메모

- 빠른 입력과 저장이 첫 화면에서 끝나야 한다.
- 기존 저장, 임시 저장, 수정, 삭제, 고정, 검색 동작은 유지한다.
- 추천 태그, 전체·즐겨찾기 필터, 최근 메모 목록을 모바일 한 열로 구성한다.

### 일정

- 오늘, 예정, 완료 수치와 주간 날짜 선택을 제공한다.
- 전체, 예정, 완료 필터와 알림 권한 안내를 제공한다.
- 시간순 목록, 상태 표현, 일정 추가 버튼을 작은 화면에서도 가리지 않게 배치한다.

### 더보기와 하위 모듈

- 더보기의 핵심 모듈은 운동, 가계부, AI 여행이며 독서는 제외한다.
- 운동은 시간·종류 선택, 선택 신체 정보, 날짜·시간·메모, 일정 동시 등록과 저장을
  제공한다.
- 가계부는 월 예산 요약, 카테고리별 금액, 지출·수입 입력, 최근 거래를 제공한다.
- AI 여행은 국가·목적지·출발일·여행 일수·인원과 취향 조건을 단계적으로 입력하고,
  선택 조건을 확인한 뒤 계획을 만들게 한다.

## 작업 재개 순서

1. `git status --short`와 `git diff --stat`으로 기존 변경을 확인한다.
2. 관련 파일의 현재 diff를 읽고, 담당 범위 밖의 변경은 수정하지 않는다.
3. 작업 트리가 깨끗할 때만 `git pull --ff-only`로 원격 변경을 받는다. 변경이 남아
   있으면 임의로 reset, checkout 또는 stash하지 말고 먼저 작업 소유자와 범위를 맞춘다.
4. 화면 단위로 구현하고 `/app` 진입, 네 개 하단 탭, 독서 진입점 부재를 확인한다.
5. 웹 빌드, 운영 Docker 빌드, 모바일 뷰포트와 설치 조건을 차례로 검증한다.

## 빌드와 검증

```bash
npm --prefix apps/web run build
docker compose -f docker-compose.dev.yml build web
docker compose -f docker-compose.dev.yml up -d --no-deps web
curl -I http://localhost/app
curl -I http://localhost/@vite/client
git diff --check
```

- `/app`이 정상 응답하고 `/`이 `/app`으로 인계되는지 확인한다.
- 홈, 메모, 일정, 더보기와 운동, 가계부, AI 여행을 모바일 뷰포트에서 확인한다.
- 키보드 표시, 화면 회전, 하단 safe area에서 입력창과 주요 버튼이 가려지지 않아야 한다.
- manifest, 서비스 워커, 앱 아이콘과 독립 실행 모드를 확인한다.
- 독서 메뉴·카드·일정 예시·캐시 자산·전용 번들이 남지 않았는지 검색한다.
- `@vite/client`는 운영 Nginx에서 404가 정상이다.

Android 래퍼는 현재 웹 빌드 산출물을 APK 자산으로 포함해 서버가 없어도 로컬 기록 화면을
열 수 있게 한다. 서버 기능이 필요하면 앱의 연결 설정에서 사용자가 `http(s)` 주소를
입력한다. 내부 주소를 하드코딩하지 않는다. 재현 가능한 래퍼 소스와 테스트한 debug APK는
이 비공개 전달 저장소에 함께 보관하되, 빌드 디렉터리와 keystore는 절대 커밋하지 않는다.

```bash
scripts/build_android_apk.sh
# 산출물: apps/mobile/android/release/ai-assitant-debug.apk
```

## 개인정보와 산출물 규칙

- 이메일 주소, 사용자 계정, 개인 메모, 원본 대화, 세션 파일 경로를 문서나 커밋에
  남기지 않는다.
- 사설 IP, 내부 저장소 주소, 토큰, 비밀번호, 서명 키를 소스와 APK에 포함하지 않는다.
- 외부 전달은 사용자가 승인한 채널에서만 수행하고, 전달 주소나 인증 정보는 로컬
  환경 설정으로만 취급한다.
- 화면 캡처와 테스트 데이터는 가상의 값으로 만들고 개인 데이터가 보이면 공유하지 않는다.
