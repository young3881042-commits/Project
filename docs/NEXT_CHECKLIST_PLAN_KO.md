# ai-assitant 작업 체크리스트

## 운영 기준

- 기본 앱 화면은 `/app`으로 사용한다.
- 루트 `/`은 별도 메인 화면을 렌더링하지 않고 `/app`으로 넘긴다.
- 포트폴리오 공개 화면은 `/portfolio`로 분리한다.
- 개인 데이터 연결 화면은 `/connect`로 둔다.
- 현재 제품은 완성된 AI 비서가 아니라 모바일 우선 메모/일정 앱으로 본다.
- `개인 AI 비서`와 `개인 데이터 허브`는 메모, 일정, 여행 보조 API가 안정된 뒤 단계적으로 붙이는 장기 방향으로 둔다.
- 장기 목표는 사용자가 휴대폰에서 권한을 준 문자, 메일, 로컬 파일, 날씨, 위치 기반 주변 장소 데이터를 개인 AI 비서 입력으로 연결하는 것이다.
- 앱 홈에는 `오늘 일정`, `메모`, `여행 코스`를 간결한 진입점으로 노출하고, 공통 메뉴에는 `연결`도 함께 노출한다.
- UI 작업은 모바일 터치 UX, 읽기 쉬운 카드, 좁은 화면 스크롤, 배포 URL/포트 안정성을 우선한다.
- 앱 홈에는 `Guest`와 `Member` 시작 창을 작게 노출하되, 기능 카드의 바로가기와 중복되는 링크 묶음은 두지 않는다.
- `/login`과 `/signup`은 여행/일정 화면 안이 아니라 앱 전용 계정 화면으로 분리한다.
- `/login`, `/signup`, 앱 홈의 Guest 시작은 기본 완료 후 `/scheduler`로 이동한다.
- 비밀번호는 복호화 가능한 암호화가 아니라 BCrypt 단방향 해시로 저장하고, 신규/변경 비밀번호는 8자 이상에 영문, 숫자, 특수문자를 모두 포함해야 한다.
- 작업 관리는 `admin1` 계정의 메모 보드에서 진행한다.
- 완료한 작업은 `admin1`의 `메모 보드`에 작업 로그로 남긴다.
- 스케줄러는 메모 보드의 메뉴로도 열 수 있어야 한다.
- Codex 작업은 시작 전 이 체크리스트를 확인하고, 완료 시 변경 로그와 필요한 후속 작업을 갱신한다.
- 실행/배포 문서는 Docker 기준으로만 유지한다.
- 외부 웹 접근 포트는 `80`으로 본다. Docker 배포/검증은 `WEB_HTTP_PORT=80 WEB_HTTPS_PORT=443` 기준으로 실행하고, `WEB_HTTP_PORT=18000`은 80 포트가 실제로 막힌 경우의 임시 우회로만 쓴 뒤 최종 상태는 80으로 되돌린다.
- 일반 웹 수정 작업은 web/API와 Docker 배포 검증, 커밋, `git push`까지 기존 흐름대로 마무리한다.
- Docker 검증 명령은 특별한 충돌이 없으면 `DB_PORT=13306 API_PORT=18080 WEB_HTTP_PORT=80 WEB_HTTPS_PORT=443 docker compose -f docker-compose.dev.yml up -d --build api web`를 사용한다.
- 일반 작업 흐름의 파일 수정, 검증, Docker web/API 배포, 커밋, `git push`는 매번 사용자에게 재확인하지 않고 진행한다.
- PWA, APK 빌드/배포, 모바일 설치 검증은 사용자가 명시적으로 요청한 경우에만 작업 범위에 넣는다.
- CI/CD는 먼저 web/API 빌드와 Docker 검증 중심의 얇은 안전망으로 검토하고, 자동 운영 배포는 별도 요청 전까지 보류한다.
- 모바일 설치 앱은 먼저 PWA 설치 흐름을 안정화하고, 로컬 메시지 접근이 필요해지는 시점에 Android/iOS 네이티브 권한을 붙일 수 있는 TWA 또는 Capacitor 구조를 검토한다.
- README식 운영 설명이나 범용 서버 운영 항목은 제품 핵심 작업 큐에서 제외하고, 필요 시 Docker 배포 점검으로만 다룬다.

## 개선 방향

1. 현재 제품 중심을 모바일 우선 메모/일정 앱으로 둔다.
   사용자는 `/app`, `/notes`, `/scheduler`에서 메모를 남기고 오늘 일정과 할 일을 빠르게 확인한다.
2. UI 완성도를 먼저 올린다.
   작은 화면에서 카드, 버튼, 입력, 스크롤이 겹치지 않게 다듬고 메모 작성/편집/삭제 흐름을 터치 기준으로 점검한다.
3. AI와 개인 데이터 허브는 API를 작게 붙이며 확장한다.
   Gmail, 네이버 메일, 로컬 메시지, LLM 키 연동은 사용자 동의와 보안 저장 설계가 준비된 범위부터 추가한다.
4. 라우팅 기준을 `/app`, `/portfolio`, `/connect`로 정리한다.
   `/app`은 앱 홈, `/portfolio`는 외부 공유용 소개, `/connect`는 개인 데이터 연결과 권한 관리를 맡고 `/`은 `/app`으로 이동한다.
5. 외부 데이터 연결은 공식 API와 사용자 동의 기반으로만 진행한다.
   Gmail은 공식 Gmail API OAuth를 사용하고, 네이버 메일은 공식 메일 읽기 Open API가 확인되기 전까지 IMAP/앱 비밀번호 방식으로 둔다.
6. 로컬 메시지는 웹/PWA 단독 접근 대상에서 제외한다.
   SMS, 카카오톡, iMessage 같은 로컬 메시지는 Android/iOS 네이티브 권한과 플랫폼별 정책 검토가 필요한 후속 작업으로 관리한다.
7. LLM 키는 로그인한 사용자별 키 등록을 기본 정책으로 둔다.
   OpenAI/Gemini 키는 서버 공용 키로 대체하지 않고 사용자별 암호화 저장, 권한 범위, 삭제 기능을 설계한다.
8. 앱화는 단계적으로 진행한다.
   Docker Web → PWA 설치 → HTTPS/도메인 → Google Play TWA 또는 Capacitor 순서로 간다.
9. 데이터 신뢰 기준을 명확히 한다.
   Google scraping은 제외하고 TourAPI, 공식 API, OSM, Wikimedia, 직접 시드 데이터만 사용한다.

## 실제 사용 기능과 경로

| 기능 | 경로 | 용도 |
| --- | --- | --- |
| 모바일 앱 홈 | `/app` | 오늘 일정, 메모, 여행 코스 진입 |
| 앱 계정 | `/login`, `/signup` | 앱 전용 로그인과 회원가입 |
| 포트폴리오 웹 | `/portfolio` | 외부 공유, 기술 스택, 주요 기능 소개 |
| 개인 데이터 연결 | `/connect` | 이메일과 문자 중심의 개인 데이터 연결 관리 |
| AI Trip | `/destinations`, `/planner`, `/plans`, `/mypage` | 장소 보기, 일자별 여행 코스 만들기, 저장 일정 확인 |
| 개인 스케줄러 | `/scheduler`, `/notes` 안의 스케줄러 메뉴 | 할 일, 반복 일정, 메모 연동 일정 관리 |
| 메모 보드 | `/notes` | 작업 카드, 메모, 파일 연결, 스케줄러 메뉴 관리 |
| 관리자 운영 화면 | `/analysisadmin` | admin1 전용 파일/운영 점검. 제품 핵심 UX와 분리 |
